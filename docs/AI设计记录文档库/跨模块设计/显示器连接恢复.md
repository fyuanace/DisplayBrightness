## 故障与目标

- 长时间运行后，原物理显示器句柄可能无法继续通信。
- 唤醒阶段，DDC/CI 响应可能暂时失败。
- 读取失败后要恢复连接，再尝试用户已确认的亮度。
- 同型号屏幕必须按设备标识匹配，避免操作相邻屏幕。

## 通信恢复

| 步骤 | 行为 |
| --- | --- |
| 首次读写 | 每台显示器的命令串行执行。读取亮度后计算该设备范围内的目标值。 |
| 短暂失败 | 最多尝试三次，两次等待分别为 250 和 500 毫秒。无效亮度范围也进入重试。 |
| 重建连接 | 枚举当前物理显示器，只接受唯一且设备标识相同的结果。接管新句柄并释放旧句柄及其余枚举句柄。 |
| 重建后重试 | 等待 500 毫秒，再执行一次完整读写流程。单次调用最多重建一次连接。 |
| 写入通道切换 | 高层亮度接口写入失败时，读取 VCP 0x10 的亮度范围，重新计算目标值并写入。 |
| 验证 | 写入后读取设备回报。读取失败或回报未达到目标时，交给上层保留重试。 |

- 重连后重新探测读写接口。
- 设备丢失或标识存在歧义时，保持失败并返回错误。
- 句柄替换、通信和释放共享同一把设备锁。

## 目标亮度与后台运行

| 触发 | 行为 |
| --- | --- |
| 手动确认 | 保存设置。写入失败时，以设备标识保留本次目标值。 |
| 后台重试 | 每 30 秒重试失败屏幕。最新确认的目标值覆盖该屏幕的旧重试值。 |
| 刷新屏幕 | 通过设备标识继续关联失败目标。 |
| 切换同步模式 | 清除旧模式的手动重试。 |
| 启用定时 | 清除手动重试，目标亮度由当前有效计划决定。 |
| 系统恢复、解锁、显示配置变化 | 在 UI 线程排队请求恢复。空闲时重新读取屏幕，并使当前计划的历史确认失效。 |

- 后台恢复复用现有卡片，保留输入框草稿。
- 恢复与用户操作沿用同一个后台任务状态，避免并行访问屏幕。
- 错误信息进入底部固定状态区域。
- 程序退出时解除系统事件订阅并释放句柄。
- 手动失败重试队列保存在内存中。已保存的设置继续使用原有文件格式。
